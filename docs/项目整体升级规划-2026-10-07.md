### 3. 偏光镜知识库里仍指向 2D 的入口

`/knowledge/polariscope` 的 3D 入口只加在了「基本介绍」和「结构讲解」两节，其余仍是 2D：

1. 首屏主按钮「进入互动学习 →」→ `/demo/polariscope`（2D）。
2. 首屏「查看结构」「了解操作步骤」只是页内锚点，不提示有 3D 课程。
3. 「使用方法」一节的步骤说明写的是「每一步对应交互演示中的一个可点击元素」，指的是 2D 演示。
4. 「交互演示」一节的「开始学习模式」→ 2D；「挑战检测模式」→ `/detection`（其中偏光镜仍是 2D 检测模式）。
5. 「结构讲解」里折叠保留的「原仪器图片与部件标注」（2D 热点图，作对照用）。

反向也存在：3D 页左栏「进入互动学习」和页脚「继续互动学习」都跳回 2D 演示。两套之间来回跳，学员不清楚哪个是主线。

### 4. 结构性问题

- **进度只认 2D**：首页「演示 x / 3」和进度页只统计 2D 学习模式的完成记录；3D 页按当初约定不写进度。学员走完 3D 课程，首页进度不变。
- **检测只用 2D**：检测流程固定嵌入 2D 演示的检测模式，3D 页没有检测模式。
- **规则多处各写一份**：偏光镜的判定和解释文案分散在 3D 页（`domain/eyepieceField` + 页面文案）、2D 演示（页面内 6 处）、检测页、命名评估、实训报告、样品数据。上一轮的 ADR、牛眼、葡萄石问题都要分几处修改。3D 课程又新增了一份 `COURSE_RULES`。
- **视觉风格**：3D 页已统一到项目的蓝白学术风和偏光镜紫。首页的深色实验室场景是有意的氛围设计，保留。2D 演示的页眉是深蓝条，与内页白色页眉不同，属于第二梯队的不一致。
- **发布与质量**：GLB 29.5 MB 未压缩；只测过本机开发服务，没测公网冷加载和普通硬件；平板、手机真机触控未测；CI 只跑了 3 份 3D 测试，新加的课程和学员模式测试没进 CI；部分测试子集运行后进程收尾会卡约 5 分钟（原有问题，未排查）。
- **调研报告中已采纳、尚未落地**：易混对比、专家演示（示范一遍）、过程内克制提示的推广（偏光镜之外）、可访问性（键盘 / 平板操作环）。

## 二、目标形态

每台仪器统一成一条学习主线，2D 和 3D 不再并列争夺入口：

```
知识库（读）→ 引导课程（讲师演示 / 学员自学）→ 自由探索（进阶）→ 检测练习（锁步、计分）→ 命名评估 → 进度 / 图鉴
```

- **偏光镜**以 3D 为主线。2D 演示在 3D 检测模式完成前继续承担检测练习，之后降为「低配设备 / 3D 加载失败」时的备用版本。确认替代可靠之前不删除。
- **折射仪、分光镜**先套用同一套「课程外壳」（课程条、动作提示、观察卡片、讲师 / 学员切换），底下仍用现有 2D 观察窗。是否做 3D 模型，按教学收益单独评估（见第四节）。
- **规则一处定义**：判定、可下结论的条件、解释文案都在 `domain/`，课程、2D、检测、结果解释、报告都从这里取用。
- **进度语义清晰**：引导课程完成（且没有跳过步骤）算「学习」，检测练习算「掌握度」；两者都写入现有的进度存储，首页和进度页统一显示。

## 三、分阶段计划

各阶段可以独立交付和验收，后一阶段不要求前一阶段之外的改动。规模：S = 一次会话内，M = 一到两次会话，L = 多次会话，并需要真人验收。

### 阶段 0 · 收尾当前分支（S）

- 提交 `feat/polariscope-guided-course` 并开 PR；CI 加入 `polariscope3d-course.spec.ts`、`polariscope3d-student.spec.ts`。
- 按观察表做一次真人试用（讲师演示、学员自学各一次），据此修第一批问题。
- 处理已知小问题：动作提示气泡遮挡场景标签；第 3 步进入时「平行最亮」自动打勾。

### 阶段 1 · 偏光镜入口整合（S–M）

把「主线是 3D，2D 是备用」落到所有入口上：

| 位置 | 现状 | 改为 |
| --- | --- | --- |
| 知识库首屏主按钮 | 进入互动学习（2D） | 「开始学习」→ 3D 学员自学；旁边次按钮「讲师演示」 |
| 首屏「查看结构」「了解操作步骤」 | 页内锚点 | 保留锚点，结构讲解卡片以 3D 为主（已是），增加「引导课程」入口 |
| 使用方法 | 步骤文字对应 2D 元素 | 每个方法的步骤可以直接跳到 3D 课程的对应步骤（需要支持 `&step=` 深链），说明文字改为对应 3D 课程 |
| 交互演示 CTA | 开始学习模式（2D）/ 挑战检测模式 | 「3D 引导课程」/「检测练习」；2D 演示降为一行次要链接「经典 2D 演示（设备较旧时使用）」 |
| 3D 页「进入互动学习」/ 页脚 | 跳回 2D 演示 | 改为「去检测练习」；2D 演示只保留在 3D 加载失败的回退界面里 |
| 2D 参考标注图 | 折叠保留 | 保持折叠，标题改为「对照：原产品图标注」 |

同时接入进度：3D 课程完成且没有跳过步骤时，写一条偏光镜学习完成记录（与 2D 学习模式使用同一字段），首页「演示」计数随之变化。这会改变「3D 页不写进度」的现有约定，需要拍板。

### 阶段 2 · 偏光镜规则统一（M）

即最初提出、尚未实施的「统一新旧页面教学规则」：

- 新建 `domain/polariscopeRules.ts`，收拢判定（均质 / 非均质 / 集合体 / ADR / 沿光轴 / 旋光 / 双晶）、「不能下结论」的条件、各现象的标题和解释文案；`COURSE_RULES` 并入其中。
- 3D 页、2D 演示、检测页、命名评估、实训报告改为引用这一份；计分和进度的行为保持不变。
- 加一组一致性测试：同一个样品、同一种状态，各页面给出的结论和文案来源一致。
- 顺带修复 2D 演示中已知的「旋转一周」完成判断问题。

### 阶段 3 · 偏光镜 3D 检测模式（M–L）

- 3D 页增加检测模式：不显示动作提示和揭晓解释，样品名称隐藏，按步骤锁定；完成后通过与 2D 相同的 `onDetectionComplete` 写入检测会话。
- 检测流程选择偏光镜时默认嵌入 3D；WebGL 不可用、加载失败或性能过低时自动回退到 2D 检测模式，并告知用户。
- 完成并验收后，2D 偏光镜演示只作为回退使用。

### 阶段 4 · 折射仪、分光镜纳入同一主线（M，每台）

- 先把课程外壳抽成通用组件：`domain/course` 只描述步骤和完成条件；课程条、动作提示、观察卡片、完成页通用。各仪器只提供自己的步骤定义和场景适配。
- 折射仪、分光镜先在现有 2D 演示上接入引导课程和学员自学模式，知识库入口按阶段 1 的方式整理。
- 3D 模型是否值得做单独评估：折射仪的关键技能（接触液、读阴影边界、点测法）和分光镜的关键技能（光源角度、读吸收线）主要靠观察窗而不是机身结构，3D 的收益可能小于偏光镜。如果要做，沿用偏光镜的 Blender / Tripo 资产流程，费用按次申请。

### 阶段 5 · 发布质量（M）

- **3D 资产**：GLB 压缩（meshopt 或 Draco，纹理 KTX2），偏光镜目标从 29.5 MB 降到 5 MB 以内；2026-10-09 起范围扩大到全部仪器（`public/assets/3d` 合计约 79 MB，目前只有显微镜照明版已压缩）；`assets-source` 大文件已归档，保持不入库。
- **性能**：公网冷加载测试、普通笔记本和平板的帧率测试；Three.js 分包。
- **设备**：iPad / 安卓平板、手机真机的触控操作（拖环、双指缩放）。
- **可访问性**：操作环的键盘步进与读屏文本（调研报告已采纳）。
- **测试与 CI**：新规格纳入 CI；排查测试子集收尾卡顿；数值正确性继续下沉到单元测试。
- **2D 页眉**：与内页统一，改为白色页眉，或明确作为「演示态」的深色样式写进设计约束。

### 阶段 6 · 教学增强（按需，来自已采纳的调研项）

- **专家演示**：讲师演示模式里增加「示范一遍」，自动按正确步骤走完并配旁白；可复用现有课程步骤。
- **易混对比**：红宝石 / 尖晶石、祖母绿 / 海蓝宝石、翡翠 / 和田玉 / 岫玉等对比视图，不进入计分。
- **真实样品校准**：用固定样品、固定取向、带角度参照的旋转一周视频，校准目镜视场与干涉图，并确认实物尺寸与机械联动。需要用户提供素材。

## 五、边界

- 纯前端；不引入后端、账号、教师端或云端埋点（沿用调研报告结论）。
- 计分规则和检测锁步不在本规划中改动；涉及进度写入的只有阶段 1 第 1 项，需要先拍板。
- 推送、开 PR、发布、付费生成 3D 资产都需要单独确认。

## 六、执行记录

### 2026-10-07 · 阶段 1–3（分支 `feat/polariscope-integration`，基于 PR #5 的 `67b3f08`；10-08 提交为 `511e393`，经 `0a8b0e7` 合并）

阶段 0 已由 Codex 完成（草稿 PR #5）。拍板项 1 按建议执行：3D 课程「完成且没有跳过步骤」时计入学习进度。

**阶段 1 · 偏光镜入口整合**

- 知识库首屏主按钮改为「开始学习」（3D 学员自学），次按钮「讲师演示」；「交互演示」一节改为「开始 3D 引导课程 / 去检测练习」，经典 2D 演示降为一行次要链接。知识库上指向 2D 的链接只剩这一处。
- 「使用方法」：光性判定可以直接进入 3D 课程的「空载调正」一步（`&step=` 深链，进入后从地址中清除）；干涉图进入 3D 干涉图分节；多色性注明暂无 3D 练习。
- 3D 页的「进入互动学习」和页脚改为「去检测练习」；2D 演示只在 3D 场景加载失败时出现。
- 学习进度：课程完成且没有跳过步骤时，写入与 2D 学习模式相同的偏光镜学习完成记录。进度存储改为按需加载：自由探索、未完成或有跳过步骤的课程都不读写学习存储（原有「不访问存储」测试保留）。

**阶段 2 · 偏光镜规则统一**

- 新增 `domain/polariscopeRules.ts`：现象简称、勾选项文字、判断前提与「不能下结论」的条件、各现象的观察解释、干涉图要点与轴性判定做法。课程问答（`COURSE_RULES`）、3D 揭晓解释、2D 结果解释与操作要点、2D 现象勾选项、知识库干涉图提示、检测页、命名评估和实训报告都改为引用这一份。
- 合并时，同一现象取两边说明的并集：例如「始终暗」保留 2D 的举例（石榴石、尖晶石、玻璃等）和 3D 的「换 2–3 个方向复查」。
- 单元测试新增「规则文字不得复制回页面」检查：在 `src/` 中扫描关键句，规则文件之外出现即失败。
- 修复 2D 学习模式的「旋转一周」判断：原来累计转 90° 或看到一亮一暗就算转完，现在要累计转满一周（留 10° 容差），拖动和自动旋转共用同一累计；没转满时显示「已转过 x° / 360°」。2D 检测模式的判断保持原样，没有改动，以免影响计分。

**阶段 3 · 偏光镜 3D 检测模式**

- 新增 `PolariscopeDetection3D`：样品显示为「未知样品」，没有动作提示和揭晓解释，明暗曲线只显示当前位置。步骤按顺序解锁：开电源 → 调到正交 → 放样 → 在正交下连续转满一周 → 记录现象与光性（或记为「几乎不透光，透射法不适用」）。可以换方向放置；检偏器一动就重新记录。
- 保存时写入与 2D 检测模式相同的记录（`setPolariscope`、`markInstrument`、检测完成），检测流程、命名评估与计分不变。
- 检测流程选择偏光镜时默认使用 3D（按需加载）；浏览器不支持 WebGL 时直接用 2D，3D 加载失败或用户点「改用 2D 版本」时切换到 2D。
- 「转满一周」的记录规则抽成 `domain/rotationCoverage.ts`，自动转一周抽成 `useStageRotation`，3D 课程与 3D 检测共用。

**验证**：单元测试 62/62；浏览器测试全量 182/182（新增入口 3 项、3D 检测 3 项、2D 转满一周 1 项；按新规则更新了 2D 拖动辅助函数和 1 项 2D 测试）。CI 的 3D 回归分片按名称前缀收集，新规格已按前缀命名，校验脚本的预期用例数从 55 改为 61，脚本自测改为由该常量推导。测试子集运行后进程收尾卡顿仍是原有问题。

### 2026-10-09 · 第五轮（部分）· 测试收尾卡顿查明原因（Claude）

**现象**：本机多 worker 跑 `smoke` 等规格时，用例全部通过，但 worker 结束后 300 秒不退出，被强制结束，退出码 1。单 worker 运行时正常退出（smoke 32 项约 48 秒）。

**原因**：本机测试使用已安装的 Google Chrome（`playwright.config.ts` 中的 `useLocalChrome`）。品牌版 Chrome 启动时会另起 `chrome_crashpad_handler` 和 `GoogleUpdater` 辅助进程，并继承 worker 与浏览器之间的输出通道；浏览器关闭后，这些进程仍在，worker 一直等不到通道关闭。手动结束本次测试启动的这两个进程后，最后一个 worker 在几秒内退出。

以下几项已排除：卡住的 worker 中没有定时器，只剩输入输出通道；只导入 `sharp` 或应用代码的最小规格不会卡住；加 `--disable-crashpad-for-testing --disable-crash-reporter` 无效，辅助进程照常启动，该改动已撤回。CI 使用 Playwright 自带的 Chromium，不受影响。

**待定处理方式**（尚未改动）：
1. 本机安装 Playwright 自带的 Chromium（`npx playwright install chromium`，约 150 MB 外部下载），本机与 CI 使用同一浏览器；需要先确认 3D 用例在它的无头模式下帧率可以接受。
2. 继续使用本机 Chrome，在测试结束时只清理本次测试配置目录下启动的辅助进程。
3. 暂不处理：需要判断进程是否正常退出时，用 `--workers=1` 运行。

另外，排查时误结束了用户自己的 Chrome 会话的两个崩溃报告进程（按运行时长筛选时条件写错）。浏览器本身仍在运行，只是这次会话的崩溃报告要等 Chrome 重启后才恢复。
