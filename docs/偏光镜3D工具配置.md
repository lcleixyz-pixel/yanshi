## Blender 桥接扩展

官方页面版本标签为 1.0.32，实际下载包 `bl_info` 为 1.0.34，以安装包记录为准。扩展自带 WebSocket 依赖，无需另装系统 Python 包。

安装位置：`~/Library/Application Support/Blender/5.2/scripts/addons/Tripo3d_Blender_Bridge/`。

本机修订仅涉及：

- 服务保持绑定 `127.0.0.1:60600`，限定来自官方国际站和大陆站 Studio 的连接 Origin。
- 接收文件标识和格式受限，文件写入专用临时目录，避免路径越界及覆盖既有文件。
- USDZ 导入整理只处理本次新增对象，保留原场景已有对象和空物体。

这是一份有记录的本地修订，不能称为官方原版或完整安全审计。后续更新官方插件会覆盖修订，需要先复核再启用。

原始 ZIP、原始代码、补丁、下载来源、文件哈希及验证脚本保存在：

`gem-lab/tools/3d-assets/vendor/tripo-bridge/`

本地 WebSocket 正常握手、GLB 传输导入、异常 Origin、路径越界、缓存清理及保留旧场景对象均已定向验证。Chrome 中的真实 Studio 已显示“Blender connected”和“Connection success”，连接 Blender 5.2.2 LTS；见 [桥接记录](../gem-lab/tools/3d-assets/vendor/tripo-bridge/README.md)。尚未从 Studio 导出云端模型，不代表生成模型的材质或实物准确性已验收。

## 导回模型的检查入口

在 `gem-lab/tools/3d-assets` 运行：

```sh
npm run inspect:import -- /absolute/path/model.glb
```

只读取自包含 GLB，结果写到独立报告目录。外部贴图或 buffer 引用需要先打包进 GLB；入口不会请求远程资源，不自动减面、合并部件或重压贴图。原有偏光镜专用 `verify` 保留，用于正式资产与部件清单的一致性检查。

通用报告包括输入哈希、格式错误与警告、节点、网格、三角形、材质、贴图和扩展。检查结果默认保存于：

`gem-lab/assets-source/polariscope/tooling-validation/`

新增 CLI 的上游依赖审计仍有未修复的嵌套通配符拒绝服务告警；本入口仅调用固定 inspect 命令，不提供任意通配符或优化参数。具体依赖与告警见 [通用检查说明](../gem-lab/tools/3d-assets/IMPORT-INSPECTION.md) 和日期目录内的 `npm-audit.json`。不要用强制降级或全项目依赖升级来掩盖告警。

## 使用顺序

1. 在 Studio 分别生成 A、B 两组，保留原始高模 GLB 和可下载的全部贴图。
2. 优先向独立 Blender 场景导入 GLB，检查镜环、薄片、通光区域、折板、背面和材质；再保存候选 `.blend`。
3. 运行通用检查，明确格式问题与人工检查问题。0 格式错误不代表结构正确。
4. 在候选副本上整理分件、转轴、PBR 材质与网页导出；质量通过后才考虑减面和压缩。
5. 用原图、固定机位和当前网页作对照，再决定是否替换正式资产。

本轮未修改现有网页渲染方式、正式 GLB 或 Blender 母版；本次工具安装没有充值、向 Tripo 上传或发起模型生成。

官方依据：[DCC Bridge](https://www.tripo3d.ai/integrations/blender)、[Codex 插件与 CLI 替代入口](https://developers.tripo3d.ai/en/docs/codex-plugin)、[Studio 与 API 独立计费](https://www.tripo3d.ai/help/api-plugins/tripo-studiotripo-api)、[glTF Transform](https://gltf-transform.dev/cli)。
