# 3D 数字资产：社区调研与实施计划

检索日期：2026-10-05（日本时间）
状态：历史计划稿；当前实施状态见开头更新与实施验收文档。
目标项目：宝石检测实训系统 `gem-lab`，浏览器内的教学演示与练习。

## 1. 推荐结论

可以实现参考站那类“可旋转、可拆解、调参数后现象变化”的 3D 教学体验。建议采用混合流程：

**项目图片和实物依据 → 部件与动作清单 → 程序化建模／Blender 整理 → GLB 资产 → 网页交互 → 独立的教学规则与验证。**

三类资产采用不同方法：

| 资产对象 | 推荐方法 | 原因 |
| --- | --- | --- |
| 偏光镜、折射仪、分光镜 | 参考 img2threejs 的分阶段程序化建模；必要时 Blender 修形 | 关键是部件、孔洞、旋转轴、装配关系，便于操作和维护 |
| 规则刻面宝石、弧面宝石 | JewelCraft／参数化几何，另外配置网页材质 | 切工和尺寸可控，便于批量生成，避免仅靠颜色区分品种 |
| 原石、矿物、复杂不规则外观 | 有明确许可的现成模型；必要时 AI 生成候选或实物采集 | 纹理和自然形态较复杂，现成资源可能更省时间 |

首轮推荐检验三件小样：**一个可拆解仪器（偏光镜优先）、一个规则刻面宝石、一个真实矿物外观模型**。它们分别检验结构操作、玻璃与宝石材质、真实纹理三项能力。首轮不批量替换现有 28 个样品，也不重写三台仪器的教学流程。

## 2. 参考站与本项目的实际基础

[The Plane of Focus](https://sael.net/plane-of-focus/)提供镜头组装／拆解、焦距位置与光圈控制、焦平面及成像解释。公开页面依赖入口包含 Three.js 0.183.2。能确认它把三维物体、参数控制和解释性图形放在同一体验中；无法仅凭页面确定作者使用了何种 AI、建模软件或全部制作过程。

因此，本计划借鉴其交互能力，不复制镜头源码、模型或页面设计。该站没有在本次核查中提供可直接复用的开源许可，不能当免费资产包。

本地现状已现场核查：

- 现有应用是 React 18、Vite 5、TypeScript、Zustand，主要通过图片、CSS、Canvas 展示三台仪器。
- 本轮开始前主应用依赖没有 Three.js/R3F，未找到 GLB、glTF、Blender 等三维资产。
- 偏光镜已有光源、上偏光片角度、载物台角度、放样等状态，适合映射到三维部件。
- 知识库“结构讲解”是合适的首个正式接入点；计分、检测会话、命名评估继续使用原有逻辑。
- 现有仪器图片可用于外观参考，但没有查到足以证明实物尺寸和内部结构的 CAD／尺寸资料。
- 当前没有已连接的 Blender／专用 3D 生成 MCP；本次在标准应用路径和命令路径未检出 Blender。实施前需单独完成工具接入检查，不能把计划工具写成已经可用。

本地依据：[应用依赖](../gem-lab/package.json)、[知识库页面](../gem-lab/src/pages/KnowledgeBasePage.tsx)、[偏光镜交互](../gem-lab/src/components/polariscope/PolariscopeDemo.tsx)、[仪器结构数据](../gem-lab/src/data/instruments.ts)、[原有项目说明](../README.md)。

近期状态必须分清：

- 腾讯[现行云产品概述](https://cloud.tencent.com/document/product/1804/120696)已有 HY 3D 3.0／3.1，3.1 支持八视图。此次未找到对应 2.5／3.0／3.1 的官方开放权重，不能沿用 2.1 仓库就称已具备 3.1 本地生成。
- [Hunyuan3D-Buffalo1.0](https://github.com/Tencent-Hunyuan/Hunyuan3D-Buffalo1.0)是 2026-08 新研究，但本轮只见论文／展示资料，未见可运行推理代码和权重，放关注名单。
- 代码、权重、输入素材、辅助模型和输出的许可要分开。例：TripoSG／PartCrafter 的默认流程引用 [BRIA RMBG-1.4](https://huggingface.co/briaai/RMBG-1.4)，其非商业许可不能被主仓库 MIT 标签覆盖。Hunyuan、SAM 的专用许可也需单独评估。
- 首轮优先使用本地可验证的几何与已有图片；需要云生成、上传素材或租用 GPU 时，再提交具体服务、素材范围和费用上限，不能把只做计划当成调用授权。

## 6. 推荐工具组合与项目结构

### 6.1 首选组合

1. **资料与规格**：项目已有图片／仪器说明；网络资源只作补充。整理可见部件、尺寸依据、动作和未知区域。
2. **生成与编辑**：img2threejs 的程序化流程负责仪器候选；Blender Python／必要时 MCP 负责整理与导出；JewelCraft 负责规则宝石候选。AI 整体生成另做有限对照。
3. **资产交付**：GLB 保存通用网格、材质和部件层级；另保留源码／`.blend`、部件标注和教学参数。GLB 文件本身不包含整套网页教学程序。
4. **网页展示**：先采用独立、懒加载的 Three.js 场景；复杂组件化需求明确后再选择 R3F。保留当前 React 18 时需配 R3F 8，而不是直接升级到 R3F 9。[官方兼容说明](https://r3f.docs.pmnd.rs/getting-started/installation)
5. **优化与验证**：[glTF Transform](https://gltf-transform.dev/)检查、去重、减面及纹理压缩；[Khronos glTF Validator](https://github.com/KhronosGroup/glTF-Validator)验证格式；浏览器检查交互、性能、加载失败和资源释放。

本次不锁死所有依赖版本；进入实施时固定验证过的版本组合和资源哈希。上述工作尽量由脚本完成重复操作，AI 负责资料判断、建模调整和多视角对照，用户重点判断教学结构与操作是否符合真实业务。

### 6.2 宝石材质与科学模型分层

网页 PBR／折射材质可表现玻璃感、色散与内部反射，但不能自然得出偏光明暗、干涉图或折射仪读数。Khronos 的[色散规范](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_dispersion/README.md)也明确：仅加色散不足以表现宝石复杂的内部反射。

因此：

- 外观参数：颜色、粗糙度、透射、视觉折射率、光照环境。
- 几何参数：切工、尺寸、部件中心、动作范围。
- 教学参数：上下偏振片夹角、光源状态、样品类别、观测条件、适用判据。
- 证据：实际照片、尺寸、观测材料、公式来源、近似范围。

四类信息分别保存，避免为了让模型“更好看”而改变教学数据。

| 3. 完成一个仪器资产 | 建立独立部件、旋转轴、装配／拆解位置、热点和材质 | 可编辑源文件、GLB、部件 JSON、预览 | 支撑环／框保留通光孔，偏振片本体覆盖有效通光区域；光轴关系合理；旋转不会穿插；拆解可准确复位；部件选择与说明一致 |
| 4. 加入有限教学交互 | 用空载偏光说明验证“参数—现象”关系；加放样位置示意和状态边界 | 独立演示页与关键条件验证 | 仅组装、空载且开灯时，按两理想偏振片计算 0°／45°／90°对应相对强度 100%／50%／0%；放样后暂停定量亮度和读数；关灯／拆解时读数为“—”且不显示工作光路 |
| 5. 网页工程验收 | GLB 格式检查、压缩、懒加载、触控、浏览器兼容、弱性能回退；多视角复核 | 验证记录及桌面／移动预览 | 无阻断错误；模型可导入；加载失败仍有说明或原图；重复进出场景不持续增加资源 |
| 6. 接入与复制 | 验收后接入知识库“结构讲解”，随后扩展另两台仪器及少量样品 | 首批资产目录和复用规范 | 原有学习／检测流程回归通过；用户确认实训表达后再扩大数量 |

空载公式依据：[OpenStax，Polarization](https://openstax.org/books/university-physics-volume-3/pages/1-7-polarization)。100% 以两片平行时为基准，不是光源全部能量；加入宝石后同时停止按空载公式改变观察视场亮度和显示读数。光源关闭时不把相对透光率写成 0%，而是显示“—”。

首轮性能预算建议作为可讨论的验收目标，而非现有实测结果：单仪器 GLB 优先控制在 5MB 内；常用桌面争取流畅的 60fps、目标移动设备不低于 30fps；具体设备、网络与材质等级在第 1 阶段确定。若高质量折射材质超预算，设置普通与精细两档，并保留图片回退。

### 最终资产包应包括

- 可编辑源文件：程序化模型源码，或 `.blend` 及可复现脚本。
- 通用模型：`.glb`，必要时另有低精度版本；保存部件节点和默认装配状态。
- 部件数据：中文名称、说明、旋转轴、动作范围、热点、拆解位置。
- 来源信息：原始资料、作者、许可、修改范围、实际尺寸或近似说明。
- 使用预览：交互页面和缩略图；桌面／移动端的验证结果。
- 教学边界：哪些现象已建模、哪些仅是示意、哪些等待实物或专业复核。
