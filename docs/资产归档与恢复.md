# 偏光镜资产归档与恢复

## 网页运行与制作素材分别保存

当前网页使用的 `gem-lab/public/assets/3d/polariscope/structure-v1/repaired.glb`、部件清单、来源说明、回退图和公开参考图库保留在普通 Git 中。克隆仓库后，按项目说明安装依赖即可运行和构建；**执行 `npm run build` 不需要恢复外部制作素材**。

大体积制作素材、原始候选、Blender 母版、旧版本和审阅产物保存在外部保全快照中，不随普通源码提交。仓库保留必要的小脚本、参数、来源及验证记录，并以 [`archive-catalog.json`](../gem-lab/tools/3d-assets/archive-catalog.json) 记录可恢复文件的原路径、字节数、SHA-256 和分组。该清单是索引，不能替代快照中的文件。

外部快照至少包含：

```text
<snapshot-dir>/
  snapshot-manifest.json
  workspace/                 # 按原仓库相对路径保存的文件
    gem-lab/...
```

快照实际位置由保全交付记录提供。命令通过参数接收路径，不依赖某台电脑的用户名或私有目录。恢复后的小文件与已提交文件相同则跳过；存在不同内容时停止，不替换当前修改。

2026-10-07 的 `snapshot-01` 是完整保全快照；同批 `archived-assets/` 保存从工作目录归档移出的素材。**两者目前都在本机同一磁盘，尚无已验证的异机副本**，因此不具备抵御该磁盘损坏的独立备份能力。本恢复命令的 `--snapshot-dir` 应指向带 `workspace/` 的完整快照，不直接指向 `archived-assets/`。

## 恢复分组

分组的准确文件列表以仓库的 `archive-catalog.json` 为准；同一文件可以属于多个组。

| `--group` | 目的 |
| --- | --- |
| `current-master` | 恢复当前可编辑 Blender 母版 |
| `current-rebuild`（默认） | 恢复当前修整版母版、原始输入、GLB 及配套归档证据；当前清单约 174.64 MiB |
| `legacy` | 恢复旧母版、旧输出及历史制作材料 |
| `reference-gallery` | 恢复公开参考图库制作脚本使用的原始图片 |
| `all` | 恢复清单中的全部文件；不等同于恢复整个仓库或 Git 历史 |

从仓库根目录执行，先将示例中的路径替换为实际快照目录：

```sh
python3 gem-lab/tools/3d-assets/restore-archive.py \
  --snapshot-dir "/absolute/path/to/snapshot-01" \
  --group current-rebuild \
  --dry-run
```

预检通过后去掉 `--dry-run`，恢复到当前仓库的原路径：

```sh
python3 gem-lab/tools/3d-assets/restore-archive.py \
  --snapshot-dir "/absolute/path/to/snapshot-01" \
  --group current-rebuild
```

也可以恢复到新的空目录，先独立检查再用于制作：

```sh
python3 gem-lab/tools/3d-assets/restore-archive.py \
  --snapshot-dir "/absolute/path/to/snapshot-01" \
  --group current-master \
  --destination "/absolute/path/to/restored-repository"
```

`--destination` 表示仓库根目录，脚本会在其下面恢复清单列出的完整相对路径。默认目标由脚本所在仓库确定，与运行命令时的当前目录无关。

## 校验与冲突处理

恢复工具仅使用 Python 3.10 及以上的标准库，不下载文件、运行 Blender、调用云服务或安装依赖。

1. 读取仓库中的资产清单，检查格式、重复路径和分组。
2. 对本次选择的所有快照源文件核对字节数与 SHA-256，并检查目标是否已有不同内容。预检阶段不写文件。
3. 已存在且字节数与 SHA-256 相同的目标标为 `UNCHANGED`；不同内容报错退出。缺失来源或校验失败同样退出。
4. 正式恢复时先复制到临时文件，再次校验后发布到原路径；不会覆盖在预检后新出现的不同文件。完成后打印恢复/跳过数量。

`--dry-run` 会执行上述来源与目标预检，但不创建目标目录或文件。程序退出码 `0` 表示本次检查或恢复完成，非零表示失败；故障后查看错误对应的具体路径。

如果目标已经有另一版模型，请用新的 `--destination` 恢复并人工比较，保留双方文件。不要为了让恢复命令通过而删除尚未保全的工作。

## 恢复后的制作边界

- 修改现行母版前，先另存新版本；网页使用哪个版本仍由 `public/.../structure-v1/` 的实际交付文件与清单决定。
- 重建脚本固定使用原来的目录关系。因此本方案把大素材恢复到原路径，不重写模型生成逻辑。
- 运行 `repair_candidate.py` 会重建并写出同目录的 `repaired.blend`、`repaired.glb`、`manifest.json`。恢复工具本身不运行它；开始新一轮重建前，应保全或另存现有母版。
- `review-tools/render_candidate.py` 已支持独立的 `--input` 和 `--output`，可直接选择恢复目录中的模型，并将审阅结果写入新目录。
- 内部光源独立检查脚本使用 NumPy/SciPy；Blender 重建使用 Blender 自带 Python 及其依赖。制作环境与网页 npm 依赖分别管理。
- 历史渲染、日志和截图是带日期的制作证据，不应当作当前代码的自动验收结果。需要新验收时重新验证对应版本。
