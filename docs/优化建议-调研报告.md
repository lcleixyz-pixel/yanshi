>
> **生成日期**：2026-06-21
> **适用范围**：仓库内 `gem-lab/` 前端教学演示应用。当前交付边界为「纯前端、无后端/账号/班级/云端评分」。
> **阅读方式**：每条建议都标注了 *证据/出处* 与 *对应到本项目的具体代码位置*。优先级 ★★★（高性价比，先做）> ★★ > ★（更大投入/长期）。

> **如何反馈**：建议评审者对每条给出「采纳 / 暂缓 / 拒绝 + 理由」，并优先回答文末「留给评审者的开放问题」。

## 0. 当前实现基线（已核实）

以下事实由代码/配置核实，作为后续建议的依据：

- **技术栈**：Vite 5 + React 18 + TypeScript 5 + Tailwind 3 + React Router 6 + Zustand + Framer Motion。
- **三个核心演示组件体量过大（单文件）**：
  - `src/components/polariscope/PolariscopeDemo.tsx` ≈ **2786 行**
  - `src/components/refractometer/RefractometerDemo.tsx` ≈ **1660 行**
  - `src/components/spectroscope/SpectroscopeDemo.tsx` ≈ **1494 行**
  - 三者合计约占 `src/components` 60%。
- **物理仿真/评分逻辑散落在组件与页面内**：`computePhenomenonBrightness`、`computeUpperPolarTransmission`（polariscope）、`recommendMethod`、`identifyChromophore`（spectroscope）、`computeScore`/`checkRI`/`checkOptical`（`pages/NamingAssessmentPage.tsx`）。
  - 已有正面范例：`src/components/refractometer/refractometerObsUtils.ts` 把折射仪纯函数独立出来，并被 `tests/smoke.spec.ts` 直接 import 测试。
- **步进状态机在三个 Demo 中各写一遍**：`STEP_ORDER` / `computeCurrentStep` / `isStepDone` / 级联失效逻辑重复。
- **测试**：仅 Playwright（`tests/smoke.spec.ts` + `tests/matrix.spec.ts`）。**无 Vitest/Jest 单元测试运行器，无 ESLint/Prettier**。
  - `tests/smoke.spec.ts` 含 **48 处** `boundingBox` / 像素坐标断言（脆弱）。
  - 现状下纯函数（如 `getFacetPolarizerMaskAlpha`）是通过整套浏览器 E2E 来测的。
- **状态管理**：`store/progressStore.ts` 用 `persist`（localStorage，key `gem-lab-progress-v1`）；`store/detectionStore.ts` **未持久化**。
  - `pages/DetectionWorkflowPage.tsx` 第 44 行注释「允许刷新继续」，但 detectionStore 为纯内存——刷新会丢失整个检测会话（意图与实现矛盾）。
  - `DetectionWorkflowPage.tsx` 与 `NamingAssessmentPage.tsx` 均 `const session = useDetection()`，**未带 selector**，订阅整个 store。
- **类型设计**：`refractiveIndex: number | [number,number] | 'over-1.78'` 联合类型，其三分支收窄在 ~7 个文件中重复。
- **数据**：28 个样品；id↔中文名映射在 `src/data/samples.ts` 与 `scripts/prepare-assets.ts` 各维护一份。
- **构建产物**：`SpectroscopeDemo` chunk ≈ 173KB（gz 54KB）。路由级懒加载已启用。
- **CI**：`.github/workflows/frontend-demo.yml` 仅在 push/PR 到 main 跑 `npm run build` + `npm run test:smoke`（不含 matrix、不含 lint）。

## 第一部分 · 教学效果提升建议（基于社区研究证据）

> 共性结论：本项目已天然符合多条循证原则——分段化步骤（Mayer Segmenting）、Canvas 实时因果反馈（PhET responsive feedback）、旋钮/圆环真实控件映射、锁步式生产性约束、命名评估的特征对比表与混淆分析（Shute 形成性反馈）。以下为可进一步提升的点。

### 速查表

| 优先级 | 措施 | 证据依据 | 复用的现有代码 |
|---|---|---|---|
| ★★★ | 预测 + 自我解释提示 | 生成式加工 / 形成性反馈 | 三个 Demo、`NamingAssessmentPage` |
| ★★★ | 积分 → 掌握度图鉴 / 解锁式进阶 | gamification 元分析 | `progressStore`、`data/samples.ts` |
| ★★★ | 抽样偏向错题（检索练习/间隔重复） | 检索练习 | `handleDrawSample`、`detectionHistory` |
| ★★★ | 「易混对比」模式 | 对比式学习 | `data/samples.ts` 现有数据 |
| ★★ | 自由探索沙盒 + 功能探索覆盖度 | PhET 隐式脚手架 | 各 Demo 的 step-lock |
| ★★ | 过程内即时形成性提示 | Shute 即时反馈 | Refractometer / Spectroscope |
| ★★ | 可导出「检测报告」产物 | 情境化虚拟实验 | `NamingAssessmentPage` 汇总 |
| ★ | 视觉做减法（观察区零干扰） | Mayer Coherence/Signaling | `HomePage`、Assessment 装饰 |
| ★ | 键盘 / 平板可访问性 | PhET 包容性设计 | 旋钮/圆环控件 |
| ★ | 教师/班级薄层（本地导出会话） | 虚拟实验作为课堂补充 | `progressStore` 历史 |

### 详细说明

**1.（★★★）预测 → 验证 + 自我解释**
研究中效果最稳的做法之一是让学习者「先预测、再操作、并说明依据」（Mayer 生成式加工 / guided-discovery）。
- 偏光镜转台前弹出「预测：转 360° 会出现?（四明四暗/全暗/全亮）」，转后揭晓。
- 命名评估提交前，让用户勾选「主要判断依据：RI / 光性 / 光谱」，再进反馈。几乎零成本，把被动点选变主动推理。

**2.（★★★）积分升级为「掌握度 + 收藏图鉴」**
gamification 元分析结论明确：积分/徽章**仅在挂钩学习目标并汇入可见进阶/解锁时**才有效；孤立计数器几乎无效；纯竞争会拉大差距，应优先「个人进步/掌握」。
- 现状：首页只展示扁平 `totalPoints`。建议改为「已掌握 X/28 宝石」图鉴墙（答对 N 次点亮），以掌握度解锁中/高级难度，而非一开始全开放。复用 `progressStore.detectionHistory` + `SAMPLES`。

**3.（★★★）抽样偏向错题**
`handleDrawSample` 当前为纯 `Math.random()`。改为对历史答错/未测样品加权抽取，即低成本实现间隔重复 / 检索练习。

**4.（★★★）「易混对比」模式**
`data/samples.ts` 已内置大量经典对照：红宝石 vs 红色尖晶石（风琴管光谱）、祖母绿 vs 海蓝宝石（同族同 RI、谱不同）、各类玉石。对比式学习显著促进迁移。做一个并排对比两块宝石三项数据的视图即可，几乎只用现有 `characteristics`/`spectrum`。

**5.（★★）自由探索沙盒 + 探索覆盖度**
PhET 核心是「guide without feeling guided」：过度显式引导利于首跑，但抑制探索与迁移。
- 检测/首次学习保留强引导；学习模式增加「自由探索」开关，解除锁步。
- 像 PhET 那样统计功能探索覆盖度（其指标如「23 个功能平均探索 18 个」），用于发现没人碰的控件。

**6.（★★）过程内即时形成性提示**
Shute：反馈应及时、具体、非评判。现状反馈集中在评估末尾。可在测量时即时提示（如折射仪读数明显偏离可达边界时给一句轻提示）。

**7.（★★）可导出检测报告**
情境化虚拟实验研究指出其能提升科学报告写作与成绩。在评估页生成可打印/导出的检测报告（三仪器数据 + 推理 + 结论），给学生有形产物，便于课堂作业。

**8.（★）视觉减法**
Mayer Coherence：排除无关装饰利于学习。氛围装饰（首页噪点/光晕、评估页 ✨）无碍，但**观察/读数区应保持高对比、零干扰**。

**9.（★）键盘/平板可访问性**
PhET 的大规模采用源于包容性设计。当前旋钮/圆环仅指针拖拽、布局桌面专属。课堂常用平板，建议控件支持键盘步进、布局适配平板。

**10.（★）教师/班级薄层**
虚拟实验作为「课堂补充」效果最佳。当前无后端，可先做本地导出会话/班级汇总，为未来教师视图留接口。

## 第二部分 · 实现方式 / 工程质量重构建议

> 以下均为**纯重构、不改变教学行为**的改进；第一条同时为第一部分的新功能打下可测试地基。

### 速查表

| 优先级 | 措施 | 解决的实际问题 |
|---|---|---|
| ★★★ | 抽纯仿真/评分模块 + 引入 Vitest | 2786 行上帝组件、物理无快速测试 |
| ★★★ | 共享 `useGuidedSteps` / `useInstrumentDemo` hook | 三 Demo 重复步进机与保存逻辑 |
| ★★ | E2E 去像素化，正确性下沉单测 | 48 处脆弱坐标断言阻碍重构 |
| ★★ | detectionStore sessionStorage 持久化 | 注释承诺「刷新继续」但会丢会话 |
| ★★ | `useDetection` 加 selector | 整 store 订阅导致全页重渲染 |
| ★★ | `normalizeRI` 归一化层 | 联合类型 7 处重复收窄、易漏判 |
| ★ | prepare-assets 从 SAMPLES 派生 + 数据校验 | 两份 id↔名映射会漂移 |
| ★ | ESLint + 类型检查 job + 定时 matrix | CI 覆盖不全、无 lint |
| ★ | Canvas 加 aria-live / 键盘 | 读屏不可见、控件仅鼠标 |
| ★ | 评估依赖 Framer Motion 体积 | SpectroscopeDemo 173KB chunk |

### 详细说明

**1.（★★★）拆解三个「上帝组件」**
每个 Demo 把物理仿真 + 步进状态机 + 视图 + 引导浮层 + QA 预设 + 学习/检测分支全塞进一个组件函数。沿已有范例 `refractometerObsUtils.ts` 继续拆：
- **物理仿真抽成纯模块**（如 `src/domain/polariscopeOptics.ts`、`spectroscopeModel.ts`、`scoring.ts`），无 React 依赖，领域专家可独立审、可单测。
- **抽共享步进机 hook** `useGuidedSteps(stepConfig)`，三处复用；保存逻辑（`setXxx + markInstrument + onDetectionComplete + markDemoComplete`）、未知样品隐藏、qaReady 预设、模式切换收进 `useInstrumentDemo`。
- 预期单文件从 1500–2800 行降到 400–600 行。

**2.（★★★）引入 Vitest 单元测试**
当前无单测运行器；纯函数靠 Playwright 浏览器测，慢且重。引入 Vitest（与 Vite 同生态、零额外配置），对抽出的纯函数全量单测：Malus 律、`riToY`、`isSpotBisected`、`checkRI` 边界、`computeScore` 奖惩、`identifyChromophore` 各致色谱。毫秒级、CI 常驻。

**3.（★★）E2E 去像素化**
`smoke.spec.ts` 48 处精确坐标断言对布局/样式改动极敏感，会惩罚上面的重构。物理/数值正确性下沉到 Vitest 后，E2E 仅保留行为断言（出现什么、能否提交、未知样品名不泄露），保留极少数真正关乎引导箭头位置的几何检查。

**4.（★★）detectionStore 持久化**
`DetectionWorkflowPage` 注释「允许刷新继续」与「纯内存 store」矛盾——刷新会丢样品与已测数据。给 detectionStore 加 **sessionStorage 持久化**（会话级、关页即清，语义贴合），真正兑现刷新继续。

**5.（★★）`useDetection` 加 selector**
两个页面订阅整个 store，任意字段变化触发整页重渲染。改为按字段取（`useDetection(s => s.refractometer)`）或 `useShallow`。

**6.（★★）`normalizeRI` 归一化层**
`refractiveIndex` 联合类型的三分支收窄在 7 个文件重复，漏判 `'over-1.78'` 即 bug（`checkRI` 已为它打补丁）。提供 `normalizeRI(ri): {kind:'single'|'range'|'over'; lo; hi}`，各处只消费归一化结果，收窄只写一遍、测一遍。顺带可清掉 `DetectionWorkflowPage` 末尾 `void formatRI;` 的 hack。

**7.（★）数据单一真相 + 校验**
让 `prepare-assets.ts` 的复制清单从 `SAMPLES` 派生，消除两份 id↔名映射漂移。加数据校验（可作 Vitest）：每样品图存在、`spectrum.features` 波长落在 400–700、RI 区间 lo≤hi。

**8.（★）CI 补齐**
现仅 build + smoke。增加 ESLint + 仅类型检查 job；`test:matrix`（84 用例较慢）放定时/夜间，不必每 PR。

**9.（★）Canvas 可访问性**
观察窗为命令式 Canvas，读屏不可见。复用已暴露的 `data-phenomenon` / `data-stage-angle`，给观察区加 `aria-live` 文本（如「当前：亮位/全暗」）——既无障碍，又让 E2E 基于语义文本断言。旋钮/圆环补 `role="slider"` + 方向键。

**10.（★）依赖体积**
确认 Framer Motion 的使用是否值回其体积；许多微动效用 `global.css` 已有的 `animate-*`（CSS）即可。拆完上帝组件后 chunk 体积会自然下降。

## 第三部分 · 建议的推进顺序（把两部分串起来）

1. **先打地基（工程 ★★★）**：抽纯仿真/评分模块 + 引入 Vitest。→ 让物理正确性可被快速验证。
2. **再降耦合（工程 ★★★/★★）**：共享步进机 hook、E2E 去像素化、`normalizeRI`。→ 让 Demo 文件可改。
3. **随后做高价值教学功能（效果 ★★★）**：预测提示、掌握度图鉴、错题加权抽样、易混对比——此时它们落在已拆出的纯模块上，天然可测。
4. **最后扩面（★）**：可访问性、平板、检测报告、CI/lint 完善。

## 第四部分 · Codex 逐条评审意见（2026-06-21）

### 评审原则

本次评审以当前开发目的为边界：`gem-lab` 是**纯前端、浏览器内运行、面向课堂/自学的宝石检测教学演示**，不是后端教学平台、账号系统、教师端或真实鉴定系统。因此：

- 优先采纳能提升「学生主动推理、检测练习、反馈闭环」的改动。
- 工程重构必须服务于可验证、可维护和后续教学功能，不为了抽象而抽象。
- 不引入后端、账号、云端评分、班级管理等能力；涉及导出/教师场景时，仅限本地文件或浏览器打印。
- 新增依赖、CI 变重、玩法锁定等会改变开发/课堂使用方式的事项，实施前需要单独确认。

### 第一部分：教学效果建议评审

| 原建议 | 评审结论 | 评审意见 |
|---|---|---|
| 预测 + 自我解释提示 | **采纳，第一批做** | 与教学目标高度一致，能把「看演示」变成「先判断、再验证」。建议先落在偏光镜与命名评估：偏光镜操作前做一次预测，评估提交前选择主要依据。注意不要每一步都弹窗打断流程，可用轻量选择卡或侧栏问题。 |
| 积分 → 掌握度图鉴 / 解锁式进阶 | **部分采纳** | 「掌握度图鉴」采纳，适合把已有 `detectionHistory` 变成可见学习进度；但「硬性解锁中/高级」暂缓。当前项目是演示交付版，课堂老师可能需要直接演示高级样品。建议先做软解锁/推荐进阶：显示“建议先完成 X 个初级样品”，但保留手动进入。 |
| 抽样偏向错题 | **采纳，第一批做** | 与检索练习目标一致，且可纯前端实现。建议抽样策略为「未测样品 + 历史错题加权 + 少量随机探索」，避免学生一直抽到同一错题。界面上可标注“练习会优先复习薄弱样品”，保持教学透明。 |
| 「易混对比」模式 | **采纳** | 很符合宝石鉴定训练：同族、同色、同 RI 或同光谱特征的对比能提升迁移。建议先做数据驱动的学习视图，不进入检测流程评分；首批对比组可选红宝石/尖晶石、祖母绿/海蓝宝石、翡翠/和田玉/岫玉。 |
| 自由探索沙盒 + 功能探索覆盖度 | **部分采纳，分阶段** | 「自由探索」采纳，可放在学习模式中作为开关；检测模式仍应保留锁步，避免破坏训练闭环。「探索覆盖度」先作为本地调试/后续分析能力，不优先做成正式学习指标，也不做远端埋点。 |
| 过程内即时形成性提示 | **采纳** | 符合教学演示目的，但提示要克制。建议只在明显偏离、长时间无进展、或提交前关键数据缺失时出现，文案使用“可以再观察……”而不是“错误”。 |
| 可导出「检测报告」产物 | **部分采纳** | 采纳本地可打印/可保存的检测报告页面，适合作为课堂作业产物；暂不做 PDF 生成依赖、教师收集、班级汇总或云端提交。可优先使用浏览器打印样式和本地 JSON/文本导出。 |
| 视觉做减法 | **采纳，作为设计约束** | 观察区、读数区和记录区应优先清晰准确；首页氛围感可以保留。后续 UI 调整时把“读数可辨、控件不遮挡、反馈不抢观察区”作为验收项。 |
| 键盘 / 平板可访问性 | **采纳，渐进推进** | 平板很可能是课堂真实场景，旋钮/圆环应支持触控与键盘步进。优先补 `role="slider"`、方向键、可见焦点和 1024px 左右布局；完整读屏体验可排在第二阶段。 |
| 教师/班级薄层（本地导出会话） | **暂缓** | 教师端/班级汇总超出当前交付边界。可保留“本地导出检测记录”的接口想法，但不应在本阶段设计教师视图、班级模型或管理流。 |

### 第二部分：工程质量建议评审

| 原建议 | 评审结论 | 评审意见 |
|---|---|---|

| 共享 `useGuidedSteps` / `useInstrumentDemo` hook | **采纳，但排在纯函数之后** | 三个 Demo 的步进逻辑确实重复，但不要一开始抽过大的通用 hook。建议先从最稳定的 step 状态、完成判定、级联重置抽 `useGuidedSteps`；保存逻辑、QA 预设、模式切换等差异较多的部分可等第二轮再合并。 |
| E2E 去像素化，正确性下沉单测 | **采纳，渐进执行** | 现有几何断言对布局改动敏感。建议把数值、物理、评分正确性迁到 Vitest；Playwright 继续保留路由可打开、未知样品不泄露、关键流程能提交、核心引导不遮挡等行为断言。少量几何断言仍应保留，用于验证仪器引导箭头/热点不会严重偏位。 |

| prepare-assets 从 SAMPLES 派生 + 数据校验 | **部分采纳** | 数据校验采纳，尤其是样品图存在、RI 范围合法、光谱波长合法。`prepare-assets` 是否直接 import `SAMPLES` 需要谨慎：脚本依赖源文件会把素材准备和业务数据耦合。更稳的方案是抽一个轻量 `sampleManifest`，由业务数据和素材脚本共同引用。 |
| ESLint + 类型检查 job + 定时 matrix | **部分采纳** | 类型检查和 Vitest 单测进入 CI 应优先；`test:matrix` 可放定时或手动触发，避免每次 PR 过慢。ESLint 有价值，但会带来一次性格式/规则成本，建议在重构前先只加最小规则，避免大量无关 diff。 |
| Canvas 加 aria-live / 键盘 | **采纳** | 这同时服务可访问性和测试语义化。建议先把观察结果、角度、当前现象用文本状态暴露出来，再逐步补键盘操作；不要为了读屏改动画或视觉表现。 |
| 评估依赖 Framer Motion 体积 | **调整为“依赖清理”，不作为性能优先项** | 当前源码中未发现 `framer-motion` import，因此它未必贡献运行 chunk 体积。建议后续确认依赖是否已闲置；若确实未使用，可移除依赖和 lockfile 记录。性能优化优先级应低于上帝组件拆分、数据/评分单测和测试策略调整。 |

### 对开放问题的当前回答

1. **重构范围**：同意「先抽纯函数 + Vitest」作为第一刀，但必须小步提交、保持现有 Playwright 行为通过。
2. **detectionStore 持久化**：倾向 `sessionStorage`；这符合“刷新继续、关页重置”的课堂演示语义。
3. **E2E 策略**：接受删减大部分像素坐标断言；保留少量验证引导定位、遮挡和核心热点可点击的几何断言。
4. **gamification 改造**：不建议先做硬性锁关；先做掌握度图鉴和软推荐，避免影响老师演示高级样品。
5. **可访问性优先级**：平板和键盘属于当前阶段合理增强；完整读屏体验可排在后续。
6. **依赖**：建议允许新增 Vitest；ESLint 分阶段；Framer Motion 先确认是否未使用，再决定是否移除。
7. **范围红线**：教师端、账号、班级、云端评分继续排除；本地打印/导出检测报告可以保留。

### 需要产品侧确认的事项

- 检测报告是否仅需浏览器打印/本地导出，是否明确不做教师收集与班级汇总？

## 第六部分 · 补充建议：面向「学员独自使用 + 提升拟真化练习效果」（2026-06-21）

> **背景**：前五部分覆盖了通用教学效果与工程质量。本部分专门从两个叠加视角补充——(A) **拟真化**：让模拟检测更接近真实台面操作的难度与判断；(B) **学员独自使用**：在没有老师在场答疑的自学场景下，补齐通常由老师口头提供的脚手架。
> **边界**：完全遵守 Codex 评审原则（纯前端、无后端/账号/教师端；掌握度软推荐；检测模式保留锁步；提示克制）。下列多数项是对已采纳条目的**延伸或具体化**，并标注与 Codex 结论的衔接关系。
> **标签**：【拟真】仿真保真度 ·【独自】无人监督自学 ·【两者】。

### 速查表

| 优先级 | 视角 | 措施 | 与 Codex 评审的关系 | 复用的现有代码 |
|---|---|---|---|---|

| ★★★ | 【独自】 | 专家演示回放（worked example，自动走一遍） | 延伸「预测+自我解释」的 worked-example 方向 | 各 Demo 的 `STEP_ORDER`/QA 预设路径 |
| ★★★ | 【独自】 | 置信度校准报告（复用已采集的 confidence） | 新增（与掌握度图鉴互补） | `NamingAssessmentPage` 的 `confidence`、`progressStore.detectionHistory` |
| ★★ | 【两者】 | 异常消光 / 缺陷样品陷阱（ADR） | 强化「易混对比」「即时提示」 | `computePhenomenonBrightness`、样品 `detectionTips` |

| ★ | 【独自】 | 「继续上次练习」+ 自定节奏目标 | 复用 Codex 已采纳的 sessionStorage | detectionStore（持久化后）、`detectionHistory` |

### 详细说明

#### A. 提升拟真化练习效果

**F1.（★★★）读数交给学员判断 + 引入测量离散性**
真实检测的核心技能是「读」与「判断」，而非系统直接给值。
- 现状：点测法 `getSpotDisplayRi` 直接算出 `1.54` 并自动填入记录（`tests/smoke.spec.ts` 亦断言 record-ri 自动等于 1.54）；刻面法边界随旋转确定性求解。
- 建议：把自动值改为**「给我看（演示）/ 我自己读」双模式**——自学时让学员自己把明暗边界读成数值并输入，系统按容差判定（容差逻辑可复用 `checkRI` 的 `TOL`）。刻面法叠加**轻微逐次抖动**，迫使学员按讲义里「每隔约 15° 读一次、取最大最小」（`instruments.ts` 已写该步骤）真正多方向读数。
- 价值：把"看一眼自动出结果"还原成"反复读数→取区间"的真实手感。需与 Codex 采纳的「过程内即时提示（克制）」配合，避免变成挫败。

**F2.（★★）锥光干涉图（黑十字 / 牛眼）补全轴性判定**
- 现状：偏光镜 `methods` 里已有「加锥光干涉球→观察黑十字/牛眼判定一轴/二轴」的步骤数据，但 `ObservationCanvas` **未实际仿真干涉图**（只有亮度场）。轴性判定这一真实关键技能目前缺失。
- 建议：新增一个简化锥光视图——一轴晶画黑十字、二轴晶画张开的孤臂、水晶画牛眼——由样品 `opticalCharacter` 驱动。这是把「数据已承诺、仿真未兑现」补齐，拟真度提升明显。

**F3.（★★）异常消光 / 缺陷样品陷阱（ADR）**
- 现状：`computePhenomenonBrightness` 对均质体一律给"完美全暗"。但数据里 `garnet`/`diamond`/`amber` 的 `detectionTips` 已写明"常见异常消光/假全暗"。真实石榴石、钻石常因应力出现 ADR，会误导学员。
- 建议：为这些样品加入**异常消光响应**（局部不完全消光/斑驳），让学员体会"偏光镜可能骗人、需交叉验证"。既是拟真，也直接教授一个重要陷阱。

**F4.（★★）「单一仪器不可区分」的强制交叉验证**
- 现状：刚玉族红宝石与蓝宝石在数据中 RI、光性、DR **完全相同**（仅颜色与光谱不同）；检测流程已建议"≥2 仪器"。
- 建议：在抽样/对比中**有意编排此类组合**，并在仅用折射仪/偏光镜时提示"该仪器无法区分，请补做分光镜"。真实鉴定就是三角互证，这能纠正"一台仪器定终身"的错误直觉。复用现有数据即可，无需新数据。

**F5.（★）感知真实感细节**
- 分光镜已建模狭缝/焦距/方法噪声（很好）。可再补：**暗适应**（弱线在数秒后才浮现）、**用手指持小样品触发 592nm 血红蛋白干扰线**（其 `limitations` 已提及但未仿真，可做成陷阱）、清洁/油量不当导致视场变糊的后果。这些把"操作纪律"变成可感知的因果。

#### B. 支撑学员独自使用（无老师在场）

**S1.（★★★）专家演示回放（worked example）**
- 自学者最缺的是"先看老师正确做一遍"。建议每台仪器加「▶ 看专家演示」——自动按正确顺序走完流程并旁白讲解（可复用现有 `qaReady` 的预设路径作为脚本）。worked-example 是文献中对新手最稳的支架之一，也契合 Codex 采纳的"预测+自我解释"方向（先看示范→再自己预测→再操作）。

**S2.（★★★）置信度校准报告（几乎零新增数据）**
- 现状：命名评估已采集 `confidence` 滑块，但只用于 `computeScore`。
- 建议：把历史里的"置信度 vs 实际正确"沉淀为**元认知校准反馈**（如"你标 80% 确定时，实际命中 62% —— 倾向过度自信"）。自学者最容易高估自己，校准反馈是低成本高价值的自我调节工具，与掌握度图鉴互补。

**S3.（★★）随叫随到的「为什么/术语」+「我卡住了」**
- 无人答疑时，学员易在术语（一轴晶/二轴晶/双折射/多色性）和"这步为什么这样"上卡死。建议：步骤旁内嵌可展开的"为什么"，术语加悬浮释义；并提供「我卡住了」按钮 + 卡顿检测（长时间无进展/反复出错才触发帮助）。这正是 Codex 对"即时提示要克制"的落地方式。

**S4.（★）对比式纠错：指出"本该做的判别性测量"**
- 现有 `generateConfusionAnalysis` 已能解释混淆原因。可深化为：答错时直接点名"区分 X 与 Y 的关键是分光镜的 ___ 谱线，你这次没测"。把纠错从"解释差异"升级为"下次怎么做"，与 F4 呼应。

**S5.（★）「继续上次练习」+ 自定节奏目标**
- 复用 Codex 已采纳的 detectionStore sessionStorage：首页提供"继续上次检测"。再加一个**软目标**（"本次练 5 个 / 攻克 2 个错题"，可跳过），契合 Codex"掌握度只做软推荐、不硬锁"的立场，给独自学习者一个自定节奏的抓手。

### 需要 Codex / 产品侧进一步确认

1. **读数交互（F1）**：是否接受"学员自行读数并输入、按容差判定"，还是保持当前自动填值（以降低自学挫败）？建议默认保留"给我看"演示、把"自己读"作为进阶开关。
2. **拟真陷阱（F3/F4/F5）**：异常消光、不可区分组合、592nm 干扰等"真实陷阱"是否会让初级难度过难？建议仅在中/高级难度启用，初级保持"干净"样品。
3. **锥光干涉图（F2）**：补一个简化干涉图仿真是否在当前交付范围内？（数据已存在，属于"兑现已承诺步骤"。）
4. **专家回放（S1）**：是否允许把 `qaReady` 预设路径复用为"演示脚本"，以零新增逻辑实现 worked example？
